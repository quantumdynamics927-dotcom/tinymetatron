# QuantumResearchLab Experiment Template

## Purpose
Every experiment follows this structure. Clone it to create a new experiment.

## Directory Structure
```
qrl-2026-XXX-experiment-name/
  MANIFEST.md          # This file — hypothesis, criteria, results
  circuit.py           # Quantum circuit implementation
  run.py               # Execution + measurement script
  results.json         # Generated by run.py
```

## Manifest Sections

### 1. Metadata
- `exp_id`: sequential ID (e.g. `002`)
- `title`: short name
- `date_proposed`: ISO timestamp
- `circuit_family`: e.g. "2-qubit Bell state", "3-qubit GHZ"
- `backend`: `simulator` | `hardware` | `both`
- `hypothesis`: one-paragraph physics hypothesis

### 2. Success Criteria
- `minimum_bar`: the pass/fail threshold
- `target`: the ideal/expected result
- `classical_bound`: the classical physics limit (for Bell tests)
- `quantum_bound`: the quantum physics limit

### 3. Implementation Notes
- `circuit_description`: what the circuit does, in plain language
- `measurement_bases`: the measurement angle choices
- `statistics`: how many shots, how S/statistic is computed

### 4. Results (filled after running)
- `date_run`: ISO timestamp
- `result_value`: the measured statistic (e.g. S value)
- `violated_bound`: which bound was violated (classical/quantum)
- `circuit_hash`: SHA256 of circuit.py at run time
- `code_commit`: git commit hash at run time

## Protocol
1. Propose: fill metadata + hypothesis BEFORE writing circuit code
2. Implement: write circuit.py + run.py
3. Validate: run simulation, compute statistic, compare to bounds
4. Report: fill results section, commit

## Safety
- Hardware submissions require explicit approval
- Simulator-only experiments are always allowed
- No credential or secret handling in experiments
